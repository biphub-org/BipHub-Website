### ✅ RESOLVED 2026-06-14 (`d088c53`) — Resubmit loop was broken (shipped a dead link)

**Fix:** new `reviseRejectedBipAction` performs the RLS-legal `rejected→draft` move (00011); the dashboard rejected card now shows a "Revise & resubmit" button that runs it and routes into the wizard; the rejection email CTA points to `/dashboard?status=rejected` instead of the 404 `/edit` deep link. E2E fixture + `resubmit.spec.ts` added (runs in the FOUN-10 sweep). `tsc`/`lint`/`vitest` (40)/`build` green. `saveDraftAction` was intentionally left untouched (avoids a stray auto-save silently withdrawing a *pending* BIP — a separate latent RLS-vs-action mismatch, tracked as a follow-up).

Original finding (for the record): a coordinator whose BIP was **rejected** had **no working path to revise and resubmit it**, and the rejection email linked to a 404:

1. `lib/queries/coordinatorBipById.ts:71` returns `null` for any status ∉ {draft, pending} → rejected BIPs cannot load the edit page.
2. `app/(dashboard)/dashboard/bips/[id]/edit/page.tsx:29` calls `notFound()` → **404** for rejected BIPs.
3. `lib/actions/bip-submit.ts:144` would block submit even if the page loaded.
4. **No Server Action performs the `rejected→draft` transition** (grep-confirmed).
5. `lib/email/templates/RejectionEmail.tsx:42` — the "Edit and resubmit →" CTA deep-links to the broken edit page. **This dead link ships to real coordinators.**

The DB was fully prepared for this (migration 00011 `USING status IN (draft,pending,rejected)`, migration 00012 `draft→pending`, `status-transitions.ts:29` declares the transition valid, migration 00010 trigger logs `action_kind='resubmit'`) — only the application wiring was never finished. It slipped through because **Phase 2's verifier was skipped per user direction** and no one exercised the cross-actor reject→resubmit flow.

**Minimal fix (one small closure slice):** (a) allow `status='rejected'` in `getCoordinatorBipById` for the edit page; (b) add an `editRejectedBipAction` (or have edit-load transition `rejected→draft`); (c) turn the rejected-card "View details" into a "Revise & resubmit" affordance. DB + state machine already support it.
