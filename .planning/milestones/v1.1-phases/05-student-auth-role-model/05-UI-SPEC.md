# Phase 5 — UI Design Contract

> Visual and interaction contract for Phase 5: Student Auth + Role Model.
> Generated by gsd-ui-researcher; verified by gsd-ui-checker.
>
> Phase 5 UI surfaces in scope:
> 1. `/register/student` — magic-link entry page; two states: (a) email-entry form, (b) "check your email" confirmation.
> 2. `/student-dashboard` — minimal but real dashboard shell: welcome header, account section, "Browse BIPs" CTA, one quiet "coming soon" line.
>
> Out of scope for this phase: saved-BIPs list, alert subscriptions, any account-deletion UI (those belong to Phase 6+).

## Surfaces: Detailed Layout Spec

### Surface 1: `/register/student` — Magic-Link Entry

**Route group:** `app/(auth)/` — inherits the existing auth layout (`min-h-screen grid place-items-center bg-bg-soft px-4 py-8`, `max-w-[440px]` card container, fixed EC disclaimer at bottom).

**Primary visual anchor:** the "Send sign-in link" button (full-width EU-blue pill).

**Layout Inheritance Note:** The existing `(auth)` layout cards on `/register` and `/login` use `p-10` (40px) as their internal card padding — this is an inherited pixel value from those existing components, not a spacing-scale token. The executor should match the existing `(auth)` card padding exactly (inheriting the live component value) rather than introducing a new token. If the existing card uses `p-10`, carry that forward as-is. If standardizing to `p-8` (32px, the `xl` token) is acceptable to avoid deviation, that is also permitted — the slight visual change is an accepted standardization trade-off. The spacing-scale section above lists only standard-set values; the auth card's inherited padding is out-of-band.

**State C — Expired link (arrival from stale magic link)**

The callback route redirects to `/register/student?error=expired`. The page renders an `Alert` component above the form in the card (matches the coordinator `/login` error pattern):

```
┌─ Alert (variant="destructive") ────────┐  shadcn Alert, mb-4 inside card
│  ⚠  This sign-in link has expired.    │  text-sm
│  Request a new one below.             │
└────────────────────────────────────────┘
[then State A form below]
```

The error code `expired` comes from `?error=expired` searchParam. The page reads this param to pre-render the Alert (RSC, no client-side flash).

**Cross-link (D-03 — ships in Phase 5):**
The "Are you a university coordinator?" line on State A is confirmed to ship. It reduces confusion for coordinators who land on the student entry point. Uses the same bottom-of-card helper text pattern as the existing coordinator pages ("Already have an account? Sign in").

**No `/login/student` page.** The page heading is "Sign in to BipHub" (not "Register" and not "Create account") because the same form handles both new and returning students — matching the magic-link UX model where new vs returning is invisible to the user.

**Welcome greeting logic:**
- If `profiles.full_name` is set: "Welcome back, [first name]" — extract first word of `full_name`.
- If `full_name` is null/empty (student profiles have no full_name in Phase 5): "Welcome back" — no comma, no placeholder.
- Email line: always show signed-in email from JWT claims. Format: "Signed in as you@university.edu" (14px text-muted).

**Card structure:**
- Use shadcn `Card` primitive (`rounded-lg border border-border bg-white shadow-sm`).
- Two cards, stacked vertically, `gap-xl` (32px) between them.
- Each card: `p-6` internal padding.
- Section headings inside cards: 16px semibold text-ink (NOT the 22px page h1 — these are content headers, not page titles).

**"Coming soon" line:**
- Plain paragraph, no Card wrapper, no icon, no badge.
- `text-sm text-muted mt-8` — quiet but present.
- Copy: "Saved BIPs and alert subscriptions are coming in a future update."
- No link, no CTA, no "notify me" box — those ship in Phase 7.

**StudentNav spec (mirrors DashboardNav):**
- `h-16 border-b border-border bg-white`
- Left: `[LogoMark]` + "BipHub" + `/` separator + "Student dashboard" label
- Right: initials avatar (`bg-eu-blue/10 text-eu-blue`, 32×32px circle, 2 initials from email local-part) + "Sign out" text button
- Sign out: `<form action={signOutStudentAction}>` → redirects to `/` (D-15), NOT `/login`; button element carries `aria-label="Sign out of BipHub"`
- No settings link in Phase 5 (no student profile editing yet)
- `aria-label="Student dashboard navigation"` on the `<header>`

**Dashboard max-width:** `960px` (not the coordinator's 1200px — student surface is content-lean; narrower feels less empty and matches auth card aesthetic).

## Interaction Contract

### `/register/student` Form

| Interaction | Behavior |
|------------|----------|
| Empty submit | HTML5 `required` + shadcn Form validation: "Please enter your email address." Inline below field, 12px text-destructive. No network call. |
| Invalid email format | Zod `z.string().email()` client-side: "Please enter a valid email address." Inline below field. |
| Valid submit | Button enters loading state: disabled + spinner icon (Lucide `Loader2`, `animate-spin`, 16px). Text becomes "Sending…". |
| Success (Supabase OTP sent) | Transition to State B (confirmation). No page reload — swap content in the card or navigate to `/register/student?step=check-email&email=...`. Prefer RSC navigation so the URL reflects state (shareable, back-button safe). |
| OTP rate limit error (Supabase 429) | Alert variant="destructive" above form: "Too many requests. Please wait a few minutes before trying again." Button re-enables. |
| Network/unknown error | Alert variant="destructive": "Something went wrong. Please try again." |
| Resend (State B) | Same rate-limit rules. Button disables for 30s after click (matches ResendVerificationButton pattern already live). Copy during cooldown: "Resent — check your inbox." |
| Expired link (State C) | Alert renders server-side from `?error=expired` searchParam. Form is pre-focused on email field. |
| Already-authenticated student visits page | Server-side redirect to `/student-dashboard` on the page component (D-13) — not middleware. |
| Already-authenticated coordinator visits page | Server-side redirect to `/dashboard` on the page component. |

### `/student-dashboard`

| Interaction | Behavior |
|------------|----------|
| "Browse BIPs" button | `<Link href="/bips">` wrapped in `<Button variant="default" size="md">` — full navigation, no modal. |
| Sign out | Form submit → `signOutStudentAction` Server Action → `supabase.auth.signOut()` → `redirect('/')`. |
| Unauthenticated access | Middleware redirects to `/register/student` (D-11 access matrix). |
| Student visits `/dashboard` | Middleware redirects to `/student-dashboard` (D-11). |

### Focus & Accessibility

- Email input on `/register/student` is auto-focused on mount (`autoFocus` on the `<Input>` element).
- All interactive elements have `:focus-visible` ring via the project's `outline-ring/50` base layer.
- Skip link ("Skip to main content") inherited from public layout — student auth layout must also have one (`position: absolute`, `class="skip-link"`), linking to `#main-content`.
- State B confirmation: focus moves to the `<h1>` "Check your email" on card transition (use `tabIndex={-1}` + `ref.focus()`).
- `aria-live="polite"` region wraps the Alert component so screen readers announce errors without requiring focus.
- Minimum touch target 44×44px on the "Send sign-in link" button and "Sign out" text button (the text button needs a `p-2 -m-2` padding expansion if its natural size is smaller).

| Rate-limit error | `Too many requests. Please wait a few minutes before trying again.` | Honest, no blame |

| Validation: empty email | `Please enter your email address.` | Native-feeling |
| Validation: invalid email | `Please enter a valid email address.` | Clear |
| Dashboard h1 (with name) | `Welcome back, {firstName}` | Personal; no punctuation after first name |
| Dashboard h1 (no name) | `Welcome back` | Clean fallback without "there" (avoids informality) |
| Dashboard email line | `Signed in as {email}` | States fact, not instruction |
| Account card heading | `Account` | Single word — unambiguous |
| Sign out button | `Sign out` (visible label); `aria-label="Sign out of BipHub"` on the button element | Lowercase; matches coordinator nav pattern; aria-label provides full context for screen readers |
| Explore card heading | `Browse Erasmus+ BIPs` | Named the product; not "Explore" alone |
| Explore card body | `Discover programmes matched to your field and availability.` | "programmes" EU spelling; value-statement not CTA |
| Browse BIPs CTA | `Browse BIPs →` | Arrow indicates navigation, not action |
| Coming soon line | `Saved BIPs and alert subscriptions are coming in a future update.` | Honest, timed to future update not "soon" |
| EC disclaimer | `Independent project — not affiliated with the European Commission` | Locked; must appear on every page |

**Tone rules (inherit from project):**
- Sentence case throughout. Never title-case UI copy.
- No exclamation marks.
- "programmes" not "programs" for Erasmus+ context. "BIPs" is always uppercase.
- Never claim EC affiliation, endorsement, or official status.
