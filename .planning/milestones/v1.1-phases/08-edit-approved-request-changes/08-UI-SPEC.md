## Spacing Scale

Declared values (multiples of 4 only):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding (gap-1) |
| sm | 8px | Compact element spacing (gap-2, p-2) |
| md | 16px | Default element spacing (px-4, p-4) |
| lg | 24px | Section padding (px-6, py-6) |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions: Diff view column header rows use `py-3` (12px) for compact
density; this matches the existing admin BipCard inner padding convention.

Source: Codebase scan of `components/admin/` and `components/dashboard/`.

## Typography

Exactly 4 declared sizes. No surface may introduce a size outside this scale.

| Role | Size | Weight | Line Height | Used for |
|------|------|--------|-------------|----------|
| Micro-label | 12px (`text-xs`) | 400 / 600 (`font-semibold`) | 1.4 | Diff column headers, char counters, mobile field prefixes, context/footer lines |
| Body / Label | 14px (`text-sm`) | 400 (body) / 600 (label) | 1.5 body / 1.4 label | All body copy, form labels, callout text, BIP-title callouts, button labels |
| Heading | 22px (`text-[22px]`) | 600 (`font-semibold`) | 1.2 | Modal titles, panel titles, page headers, diff card header |
| Display | 28px | 600 (`font-semibold`) | 1.2 | Reserved (not used by a Phase 8 surface; declared for scale completeness) |

Weights are limited to 400 and 600 only. The micro-label role uses 400 for
running context lines and 600 for emphasis labels (column headers, prefixes).

No `text-base` (16px) and no `text-[18px]` anywhere — both collapse into the
scale above (16px → 14px label; 18px → 22px heading). The 4px delta between
the original 18px diff header and the 22px heading role is imperceptible.

Source: `components/admin/AdminActionsPanel.tsx`, `components/admin/ApproveBipModal.tsx`,
`app/(admin)/admin/page.tsx`.

### New status token: `changes_requested`

This token does not yet exist in `app/globals.css` and must be added in Phase 8.
It reuses the amber palette of `status-pending` because "changes requested" is
semantically equivalent to "pending with feedback" — the same amber weight
signals "needs attention" without introducing a new hue.

| CSS variable | Value | Usage |
|-------------|-------|-------|
| `--color-status-changes-requested` | `#b45309` | Badge text on changes-requested items |
| `--color-status-changes-requested-bg` | `#fffbeb` | Badge background on changes-requested items |

Executor must add inside the `@theme inline` block in `app/globals.css`:

```css
/* ---------- Phase 8 — changes_requested status color ----------
   PITFALLS Pitfall 13: Tailwind v4 cannot resolve dynamic class names.
   Consumers MUST use the STATUS_BADGE_CLASSES literal lookup in
   lib/utils/status.ts. No template literals.

   Safelist — the static scanner MUST see these full class strings:
     bg-status-changes-requested-bg
     text-status-changes-requested
     border-status-changes-requested
*/
--color-status-changes-requested: #b45309;
--color-status-changes-requested-bg: #fffbeb;
```

Executor must also update `lib/utils/status.ts`:
- Add `'changes_requested'` to the `BipStatus` union type.
- Add `changes_requested: 'bg-status-changes-requested-bg text-status-changes-requested border-status-changes-requested'` to `STATUS_BADGE_CLASSES`.
- Add `changes_requested: 'Changes Requested'` to `STATUS_LABELS`.

Source: `app/globals.css` existing `status-pending` amber token pattern;
08-CONTEXT.md D-06a.

## Surface Contracts

### Surface 1 — Coordinator edit form: approved-BIP CTA extension

**File extended:** `app/(dashboard)/dashboard/bips/[id]/edit/page.tsx`
(the page and its `BipSubmissionWizard` render-prop area)

**Primary visual anchor:** the gold pill CTA at the bottom of the form is the
single focal point. All status callouts sit above the fields and orient
attention downward toward the action; nothing competes with the gold pill for
emphasis (status badges are amber/blue but small, callouts are low-saturation
tinted blocks).

**Slug field:** Omitted entirely when BIP is `approved` — the field must not
appear in the form DOM (EDIT-09 / D-10).

Three mutually exclusive states based on the BIP status and any open
`bip_edits` row:

#### State A — `approved` BIP, no open edit

Status indicator placed above the wizard fields:

```
┌──────────────────────────────────────────────────────────────┐
│  ✓  This BIP is live. Submit an edit to propose changes —    │
│     the public page stays unchanged until an admin approves. │
└──────────────────────────────────────────────────────────────┘
```

Markup: `rounded-md border border-eu-blue-100 bg-eu-blue-50 px-4 py-3 mb-6 flex items-start gap-2`
Icon: `CheckCircle2` size 16, `text-status-approved`, `mt-0.5`, `flex-shrink-0`
Text: `text-sm text-ink`

Primary CTA (bottom of wizard, replaces normal "Submit" button):
- Label: **"Submit Edit for Review"**
- Classes: `bg-eu-gold text-ink hover:bg-eu-gold/90 rounded-pill px-5 py-2 font-semibold w-full`
- Pending label: `"Submitting…"` with `Loader2` size-4 `animate-spin mr-2`

#### State B — `approved` BIP, open edit in `pending`

Status callout:

```
┌──────────────────────────────────────────────────────────────┐
│  ⏱  Your edit is under review. You can update fields below,  │
│     but resubmission isn't available until the admin responds.│
└──────────────────────────────────────────────────────────────┘
```

Markup: `rounded-md border border-status-pending bg-status-pending-bg px-4 py-3 mb-6 flex items-start gap-2`
Icon: `Clock` size 16, `text-status-pending`, `mt-0.5`, `flex-shrink-0`
Text: `text-sm text-ink`

CTA: disabled ghost button — `"Edit in review"` — `variant="outline" disabled rounded-pill px-5 py-2 w-full opacity-60 cursor-not-allowed`

Fields remain visible and editable in the DOM (coordinator may draft local
updates while waiting), but the Server Action for resubmit is not mounted.

#### State C — `approved` BIP, open edit in `changes_requested`

Admin-note callout (matches existing rejected-reason callout visual language):

```
┌ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┐
│  Changes requested
│
│  {admin_note verbatim}
│
│  Update your submission below, then resubmit for review.
└ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┘
```

Markup: `rounded-r border-l-4 border-eu-gold bg-eu-gold/5 px-4 py-3 mb-6`
Heading: `text-sm font-semibold text-ink mb-1`
Admin note body: `text-sm text-ink-2 mb-2`
Footer line: `text-xs text-muted`

Primary CTA: **"Resubmit Edit"** — identical classes to State A gold pill.

**Interaction contract:**
- State A CTA → create `bip_edits` row → Sonner success toast: `"Edit submitted for review. The public page stays live while it's being reviewed."` → transition to State B
- State C CTA → update existing `bip_edits` row (same row, D-05) → Sonner success toast: `"Edit resubmitted. An admin will review it shortly."` → transition to State B
- Any server error: `Alert variant="destructive"` inline above the CTA: `"Your edit could not be submitted. Try again or contact support."`

### Surface 2 — Admin review queue: type badge + `changes_requested` support

**Files extended:** `components/admin/AdminBipCard.tsx`, `components/admin/AdminBipRow.tsx`

#### Type badge

The badge appears immediately after the status pill, in the same flex row.

| Item type | Badge label | Classes |
|-----------|-------------|---------|
| New submission | _(no badge)_ | — |
| Approved-BIP edit (`bip_edits` row) | `"Edit"` | `inline-flex items-center rounded-full border px-2 py-0.5 text-xs font-semibold bg-eu-blue-50 text-eu-blue border-eu-blue-light` |

Tailwind v4 static-scanner requirement: the full class string
`bg-eu-blue-50 text-eu-blue border-eu-blue-light` must appear as a complete
literal in a lookup object (same pattern as `STATUS_BADGE_CLASSES`). Do not
concatenate.

#### `changes_requested` status support

`AdminBipCard` and `AdminBipRow` both pass `bip.status` into `STATUS_BADGE_CLASSES`.
Once `lib/utils/status.ts` is updated (see Color section), the badge renders
automatically. No additional JSX changes needed beyond accepting the updated
`BipStatus` union.

#### Queue page header copy

| Condition | Heading | Sub-line |
|-----------|---------|----------|
| 0 items | `"Pending review"` (unchanged) | `"You're all caught up"` (unchanged) |
| N items, no edits | `"Pending review"` (unchanged) | `"N BIP{s} awaiting review"` (unchanged) |
| N items, ≥1 edit | `"Pending review"` (unchanged) | `"N items awaiting review · includes new submissions and edits"` |

The sub-line update is in `app/(admin)/admin/page.tsx`. Separator is a centered
dot `·` with non-breaking spaces (` · `).

### Surface 3 — Admin diff view

**File:** `components/admin/BipEditDiffView.tsx`

Used on the admin review page when the item is a `bip_edits` row. Renders
below the breadcrumb row, replacing or preceding `BipBody`.

#### Outer card

`rounded-md border border-border bg-white shadow-sm`

#### Card header

`px-6 py-4 border-b border-border flex items-center justify-between`
- Left: `"Field Comparison"` — `text-[22px] font-semibold text-ink` (heading role)
- Right: `"{N} field{s} changed"` — `text-sm text-muted` (computed at render)
  - If 0 changes: `"No fields changed"` — `text-sm text-muted italic`

#### Column header row (desktop ≥ 960px)

`hidden md:grid grid-cols-[180px_1fr_1fr] gap-0 px-6 py-2 bg-bg-soft border-b border-border sticky top-[var(--admin-header-height,56px)]`

| Cell | Content | Classes |
|------|---------|---------|
| Col 1 | `"Field"` | `text-xs font-semibold text-muted uppercase tracking-wide` |
| Col 2 | `•` green dot + `"Live version"` | green dot: `inline-block w-2 h-2 rounded-full bg-status-approved mr-1.5 align-middle`; label: `text-xs font-semibold text-muted uppercase tracking-wide` |
| Col 3 | `•` blue dot + `"Proposed edit"` | blue dot: `inline-block w-2 h-2 rounded-full bg-eu-blue mr-1.5 align-middle`; label: same |

#### Field rows

**Desktop (≥ 960px) — unchanged field:**
`grid grid-cols-[180px_1fr_1fr] gap-0 px-6 py-3 border-b border-border hover:bg-bg-soft transition-colors`

**Desktop — changed field:**
`grid grid-cols-[180px_1fr_1fr] gap-0 px-6 py-3 border-b border-border bg-eu-gold-soft border-l-2 border-l-eu-gold`
(`bg-eu-gold-soft` = `#fff4cc` — already a token in `globals.css`)

**Cell contents:**
- Field label cell: `text-sm font-semibold text-muted self-start pt-0.5`
- Live value cell: `text-sm text-ink whitespace-pre-wrap`
- Proposed value cell: `text-sm text-ink whitespace-pre-wrap`
- Empty/null value in either cell: render `"—"` in `text-muted`

**Mobile (< 960px) — stacked layout per field:**
```
[Field label]
  Live:     [live value]
  Proposed: [proposed value]    ← only shown for changed fields
```
Changed-field wrapper: `border-l-2 border-l-eu-gold bg-eu-gold-soft px-4 py-3 mb-2 rounded-r`
Unchanged field: `px-4 py-3 mb-2 border-b border-border`
"Live:" / "Proposed:" prefixes: `text-xs font-semibold text-muted`

#### Field groups rendered in display order

1. Title
2. Short description
3. Field of study
4. Language(s)
5. ECTS credits
6. Level
7. Host city
8. Physical start date
9. Physical end date
10. Virtual start date
11. Virtual end date
12. Application deadline
13. How to apply (type + value combined as `"{type}: {value}"`)
14. Partner institutions (rendered as newline-separated list)
15. Green travel
16. Description / additional info

Slug is excluded from the diff (it is never part of the `bip_edits` payload,
per D-10).

### Surface 4 — Admin actions panel: request-changes extension

**File extended:** `components/admin/AdminActionsPanel.tsx`

Three-button layout (top to bottom within the sticky panel):

```
┌─────────────────────────────────────────────┐
│ Admin actions                               │
│                                             │
│ [  ✓  Approve BIP / Approve Edit  ]         │  gold fill pill
│ [  ↻  Request Changes              ]         │  amber outline pill (NEW)
│ [  ✗  Reject BIP / Reject Edit    ]         │  red outline pill
│                                             │
│ [helper text]                               │
└─────────────────────────────────────────────┘
```

**Button specs:**

Approve:
- Classes: `bg-eu-gold text-ink hover:bg-eu-gold/90 rounded-pill w-full` (existing, no change)
- Icon: `Check` size 16 `mr-2 aria-hidden`
- Label: `"Approve BIP"` (new submission) / `"Approve Edit"` (edit row)

Request Changes (new):
- Classes: `border border-status-pending text-status-pending bg-white hover:bg-status-pending-bg rounded-pill w-full`
- Icon: `MessageSquare` size 16 `mr-2 aria-hidden`
- Label: `"Request Changes"`
- `disabled` when: item is already `changes_requested` and no new note will be provided (modal enforces this)

Reject:
- Classes: `border border-status-rejected text-status-rejected bg-white hover:bg-red-50 rounded-pill w-full` (existing, no change)
- Icon: `X` size 16 `mr-2 aria-hidden`
- Label: `"Reject BIP"` (new submission) / `"Reject Edit"` (edit row)

**Enabled logic:**

| Button | Enabled when |
|--------|-------------|
| Approve | `bips.status = 'pending'` OR `bip_edits.status = 'pending'` |
| Request Changes | `bips.status = 'pending'` OR `bips.status = 'changes_requested'` OR `bip_edits.status = 'pending'` OR `bip_edits.status = 'changes_requested'` |
| Reject | `bips.status IN ('pending','approved')` OR `bip_edits.status = 'pending'` |

**Helper text** (inside `bg-bg-soft rounded-sm px-3 py-2` block):
- New submission: `"Approving publishes the BIP. Requesting changes returns it to the coordinator with your note. Rejecting permanently declines this submission."`
- Edit row: `"Approving merges the edit into the live BIP immediately. Requesting changes returns the edit to the coordinator. Rejecting discards the edit; the live BIP stays unchanged."`
