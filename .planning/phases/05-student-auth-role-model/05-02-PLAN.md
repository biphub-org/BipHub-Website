**signInWithOtpAction** (STUD-01 / D-01 / D-02 / D-04) — magic-link dispatch, handles both new signups and returning sign-ins via `shouldCreateUser: true`:
```typescript
// STUD-01 / D-01: single entry for new signup + returning sign-in via magic link.
// options.data.role → raw_user_meta_data at creation; the handle_new_user trigger
// (00015) reads it to set profiles.role='student'. emailRedirectTo carries
// type=magiclink so the callback routes to /student-dashboard (D-04).
export async function signInWithOtpAction(
  formData: FormData,
): Promise<{ error?: string; success?: true }> {
  const email = String(formData.get('email') ?? '').trim().toLowerCase()
  const result = z.string().email().safeParse(email)
  if (!result.success) {
    return { error: 'Please enter a valid email address.' }
  }

  const supabase = await createClient()
  const { error } = await supabase.auth.signInWithOtp({
    email: result.data,
    options: {
      shouldCreateUser: true,
      data: { role: 'student' },
      emailRedirectTo: `${SITE_URL}/auth/callback?type=magiclink`,
    },
  })

  if (error) {
    const msg = error.message.toLowerCase()
    if (msg.includes('rate limit') || error.status === 429) {
      return { error: 'Too many requests. Please wait a few minutes before trying again.' }
    }
    return { error: 'Something went wrong. Please try again.' }
  }
  return { success: true }
}
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| email magic-link → /auth/callback | An attacker-supplied or stale `code`/`type` querystring crosses into the PKCE exchange |
| browser request → middleware | Every route request passes the edge guard; role is read from the validated JWT (`getClaims`) |
| form → signInWithOtpAction | Untrusted email input enters the OTP-dispatch action |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-06 | Information Disclosure | middleware /dashboard, /admin, /student-dashboard guards | mitigate | D-11 matrix: cross-role navigation is redirected at the edge using validated `getClaims()` role; student cannot reach coordinator/admin areas (FOUN-08) |
| T-05-07 | Spoofing | /auth/callback expired/invalid magic link | mitigate | `exchangeCodeForSession` failure → redirect to `/register/student?error=expired`; no session is set on failure (SC-2) |
| T-05-08 | Spoofing (open redirect) | /auth/callback emailRedirectTo / destination | mitigate | Destinations built only from server-controlled `SITE_URL` + hard-coded paths; `type` selects among a fixed set; user querystring cannot inject an arbitrary host (T-02-02-10 preserved) |
| T-05-09 | Denial of Service | signInWithOtpAction | accept (delegated) | Supabase Auth rate-limits OTP dispatch (config.toml otp limits); action surfaces a 429-aware message rather than retry-looping |
| T-05-10 | Input Validation | signInWithOtpAction email | mitigate | `z.string().email()` (zod v3) validates server-side before any Supabase call (V5) |
</threat_model>
