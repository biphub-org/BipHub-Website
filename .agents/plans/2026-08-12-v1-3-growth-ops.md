## Goal

Close the shipped-but-unverified debt from v1.1/v1.2, then ship the two highest-leverage slices that make BipHub retain coordinators year-over-year and make students compare and share BIPs — without adding a public API or rich-text editor.

**Outcome:** a coordinator can duplicate last year's BIP into a draft (SUBM-15) with a visible "Nth edition" maturity signal (SUBM-16); a student can filter out partner-only BIPs (BROW-15), compare 2–3 BIPs side-by-side (DISC-08), and share a shortlist URL (DISC-09/GROW-01); an admin can export CSV and bulk-moderate. The outstanding Phase 8 edit-flow (EDIT-04 ISR + EDIT-07 Resend) is verified in a running env with `RESEND_API_KEY` set before any new feature work counts as done.

4. **Admin ops (TOOL-01/02):** admin can **CSV export** current filtered queue and **bulk approve/reject** (with note) from `/admin` without N round-trips silently dropping rows. Both actions audit to `bip_status_history`.

RLS: duplicate respects `bips_select_own` / `bip_edits` policies; compare/shortlist is public read (`bips_select_approved_public`); admin bulk guards `role='admin'` via `getClaims()`.

## Constraints And Non-goals

- **Stack locked — no new npm packages required:** duplicate uses existing `bips` row + `bip_edits` lineage; compare/shortlist is client state + URL query params; CSV export is `Response` with `text/csv` (no new lib). If a CSV helper is added, it must be `papaparse`-free (plain string join) unless user approves a dep.
- **One-command local dev (`supabase start` + `npm run dev`) must not break:** no Vercel Cron, no `n8n`, no new deploy target. Alert pipeline stays `pg_cron→pg_net→Edge Function` and is untouched in v1.3.
- **Non-goals (do not litigate in planning):** rich-text/WYSIWYG, photo uploads, cost/funding calculator, day-by-day itinerary, reviews/ratings, public read API, JSON-LD/schema.org, structured itinerary builder, instant per-BIP alerts — all per `REQUIREMENTS.md:80-92` + `PROJECT.md` Out of Scope. `FOUN-11/12/13` (alert RLS/cascade/privacy) are already shipped — do not reopen.
- **IRB:** no `UPDATE` policy without both `USING` and `WITH CHECK`; no table without `ENABLE ROW LEVEL SECURITY`; no `AdminClient` outside admin boundary.

## Recommended Approach

**Close debt first, then two student-facing slices, then one admin slice — 3 new phases (12–14) plus a Day 0 verification gate.** Each phase is vertically sliced (end-to-end user capability, not a layer).

- **Day 0 — Phase 8 verification gate (0-code, 1 plan):** run the 7-step `08-UAT.md` in a running env with `RESEND_API_KEY` set; confirm `EDIT-04` ISR within seconds and `EDIT-07` all 3 emails (approval/rejection/changes-requested) with link+note. No code change unless the gate finds a regression (then file a bug plan, do not silently widen RLS). On pass, flip `08-VERIFICATION.md` to `verified`, `08-UAT.md` checkboxes to `done`, close the `STATE.md` deferred row (same pattern as Phase 5 today).

- **Phase 12 — Duplicate BIP + Program Maturity (`SUBM-15`/`SUBM-16`):** DDL `00045` adds `duplicated_from_bip_id`; new Server Action `duplicateBipAction(sourceId)` clones `BipDraftData` (+ partner universities via `bip_partner_universities`) into a new `draft` row (slug regenerated via `slugify`, `status='draft'`, dates optionally nudged +1y, `created_by=auth.uid()`). Dashboard card gets **Duplicate** affordance (only on own BIPs, `approved`/`rejected`/`changes_requested` — not `pending`/`draft`). Detail page shows `Edition N` badge when `N>1` (recursive CTE `WITH RECURSIVE lineage` in `getBipEdition()`; `N` computed as chain length, not stored). Uses `getClaims()` only; no `createAdminClient`. Seeds: edit `seed.e2e.sql` + `seed-cloud-e2e.mjs` to include one duplicated chain (A→B) and `verify-seed.ts` assertion for `edition=2`.

- **Phase 13 — Discovery: exclude partner-only + compare + shortlist (`BROW-15`, `DISC-08/09`, `GROW-01` shortlist):** extend `BipFilterSchema` with `partnerOnly: z.enum(['exclude']).optional()`, plumb through `lib/queries/bipListing.ts` (add `partner_institutions_only.eq.false` when `exclude`), URL sync in `BipFiltersSidebar`/`BipFiltersDrawer` + `BipFilterChips`. Compare: client store `compareIds: string[]` (max 3, localStorage `biphub:compare` for persistence, URL is authority for sharing) + `/bips/compare?ids=` page (RSC, `Promise.all` over `getBipDetailById`, card-grid diff using existing `BipKeyFacts`/`BipBody` sections, no tables, deadline+Apply CTA prominent per DETL-16). No new tables/RLS.

- **Phase 14 — Admin ops (`TOOL-01` CSV export + `TOOL-02` bulk moderate):** `GET /admin/export.csv?status=pending&q=&country=` (admin-only Route Handler, `getClaims()` guard, `content-disposition: attachment`, streams from `getAdminPendingSubmissions`/`getAdminPendingEdits` with same filter as queue). Bulk moderate: `bulkModerateBipsAction` as described in Key Decision 5, wired to checkbox + sticky action bar in `/admin` (shadcn Checkbox + Button, no new dep). `TOOL-03` (view/save counts) deferred to v1.4 — needs analytics instrumentation first.

Reuse: `slugify` (1.6.9), `lib/utils/cn.ts`, `STATUS_BADGE_CLASSES`, `BIP_EDIT_CONTENT_COLUMNS`, `lib/supabase/database.types.ts` (regen via `supabase gen types --linked` after DDL push — never `--local` per Pitfall 2).

## Risks / Rollback

| Risk | Mitigation |
|------|------------|
| Scope creep (JSON-LD, rich text, photo uploads, public API) re-litigated during Phase 13 | Locked non-goals in this plan + `REQUIREMENTS.md:80-92` — any such request becomes a v1.4 candidate, not a v1.3 amendment. |
| `duplicated_from_bip_id` FK mishandled (`CASCADE` deletes the clone when source is GDPR-deleted) | `ON DELETE SET NULL` + derived edition (not stored counter) — deletion is safe by DDL. |
| New filter `?partnerOnly` breaks existing shared URLs (`/bips?country=de&field=business`) | Additive param, absent = show all (backward compatible). No migration of old URLs needed. |
| Bulk moderate partially fails (2 succeed, 1 fails on RLS/CONSTRAINT) | Return `{ succeeded, failed }` per Key Decision 5 — do not throw on first failure; admin sees which row to retry. No data loss; audit is per-row. |
| `database.types.ts` drift (regenerated against `--local` while deploy reads cloud) | Enforce `supabase gen types --linked` after `db push` (Pitfall 2). CI step: `grep -r "gen types --linked" .planning` already guards. |
| Phase 8 gate fails (ISR or Resend regression) | File a bug plan, do not widen RLS or invent a batch shortcut to hide it. v1.3 feature work pauses until the single-row contract is green again. |

Rollback per unit is `supabase migration repair` / `db push` revert for 12.1 plus code revert; no data migration beyond the nullable FK, so no backfill to unwind. The milestone close is docs-only and reversible.
